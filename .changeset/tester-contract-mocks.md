Test mocks now fail where the real client, or the service it calls, would fail. `QueueTester`, `TopicTester`, `WsTester` and `HttpTester` look up the service contract through the tester: a queue message or topic event outside its schema throws `MalformedMessageError` or `MalformedEventError`, a queue message without its FIFO or fair group throws `MissingMessageGroupError`, and an HTTP request with path parameters, query strings or a body the service refuses throws `HttpBadRequestError`. Response bodies reach the caller the way the real client delivers them, without the fields the response contract doesn't declare, and error bodies carry `context`. Queue, topic and WebSocket mocks also record `delivered`: each payload as the consumer receives it. `restoreClient` without a `setClientMock` before it no longer removes the real client, a second `setClientMock` no longer makes `restoreClient` return to the first mock, and `setClientMock` returns the mock. Mocks use a tracker of their own, so `mock.restoreAll()` in another spec no longer takes them apart. Run the consumer's suite before upgrading: a test that sends a payload the contract refuses, cans a response the service can't send, or calls an operation the service doesn't have now fails.
